Guida completa alla configurazione del portale: come gestire le voci di menu, i permessi per ruolo e per utente, e i due sistemi di navigazione in parallelo.

Percorso: Admin Portale (menu principale)
Versione portale: 0.8.6
Marzo 2026

1. Panoramica del sistema
Due sistemi di navigazione in parallelo

Il portale utilizza due sistemi di navigazione paralleli che coesistono durante la migrazione dal vecchio al nuovo:

SistemaDove si gestisceScopo
Pulsanti legacy Topbar Live · Gestione Pulsanti Tabella storica del portale originale. Ancora usata per la topbar e per il sistema ACL (permessi).
Navigation Builder nuovo Navigation Builder Sistema Django per topbar, subnav, sidebar e link di pagina. Può importare i pulsanti legacy.
💡
Regola pratica: per aggiungere voci al menu usa il Navigation Builder. Per modificare i permessi ACL usa Gestione Permessi (basata sempre sui Pulsanti legacy).

Flusso di verifica permessi

Richiesta utente → Middleware ACL → Cerca pulsante con modulo + codice → Controlla override utente (priorità alta) → se nessun override → controlla permesso ruolo → accesso consentito / negato
🔘
2. Pulsanti (sistema legacy)
Unità base del sistema ACL e navigazione

Un pulsante è l'unità base del sistema ACL. Rappresenta un'azione o una sezione del portale. A ogni pulsante corrispondono una voce nel menu (se abilitato) e un permesso verificabile.

📍
Percorso: Admin Portale → Gestione Pulsanti

La pagina mostra una griglia di card, una per ogni modulo. Ogni card contiene i pulsanti del modulo con i relativi toggle.

Campi principali

CampoSignificato
codiceIdentificatore univoco (slug). Non modificare dopo averlo usato nei permessi.
moduloGruppo di appartenenza (es. assenze, anomalie, assets). Usato per raggruppare i permessi.
label / nome_visibileTesto mostrato nel menu all'utente.
urlDestinazione del link. Usa route:nome_route per route Django interne.
visible_topbarSe attivo, il pulsante compare nella barra in alto.
enabledSe non attivo, il link è disabilitato (grigio) ma ancora visibile.
ui_slotPosizione nel layout (topbar, toolbar, ecc.).
ui_sectionSezione di raggruppamento visiva (es. dashboard, assenze).
ui_orderNumero d'ordine nel menu — valore più basso = mostrato prima.

Stati toggle nell'interfaccia

Verde — funzionalità attiva
Grigio — funzionalità disattiva
Giallo/parziale — solo alcuni pulsanti del modulo attivi

La riga diventa semi-trasparente durante il salvataggio (stato saving).

⚡
3. Topbar Live
Editor rapido navigazione
📍
Percorso: Admin Portale → Topbar Live

Interfaccia semplificata per modificare rapidamente la topbar senza uscire dalla pagina. Ideale per riordinare le voci o attivare/disattivare link in tempo reale.

Come usarla

  • 1
    Ogni riga rappresenta un pulsante legacy.
  • 2
    Modifica direttamente i campi nella riga.
  • 3
    Premi Salva sulla riga per applicare la modifica.
  • 4
    I toggle Topbar e Attivo si salvano automaticamente al cambio — nessun Salva necessario.

Riordinare le voci

Usa i pulsanti Su / Giù per spostare una voce, oppure modifica manualmente il campo Ord UI e premi Salva.
Il pulsante Rinumera ordine UI ricalcola tutti i numeri in sequenza multipla di 10.

Filtri disponibili

FiltroDescrizione
RicercaCerca per nome, codice, modulo o URL.
Sezione UIFiltra per sezione (dashboard, assenze, ecc.).
Vista "Solo topbar"Mostra solo le voci con visible_topbar = ON.

Catalogo route

In fondo alla pagina si trova il Catalogo route Django con tutti gli URL interni disponibili. Per i link usa il formato route:nome_route nel campo Link (es. route:dashboard_home).

ℹ️
La voce Dashboard viene sempre garantita anche se non esplicitamente presente nel catalogo.

4. Navigation Builder
Sistema nuovo — gestione centralizzata del menu
📍
Percorso: Admin Portale → Navigation Builder

Gestione centralizzata del menu senza modificare codice. Supporta topbar, subnav, sidebar e link di pagina. Le modifiche sono immediate e possono essere versionate attraverso snapshot.

Struttura di una voce

CampoSignificato
CodiceSlug univoco. Se vuoto viene generato dalla label.
LabelTesto visualizzato nel menu (obbligatorio).
SezioneDove appare: topbar · subnav · sidebar · page
Gruppo subnavSolo per sezione subnav: codice del gruppo (es. assenze). La subnav appare quando l'utente è nella sezione corrispondente.
OrdineNumero d'ordine (basso = prima). Riordinabile anche trascinando.
Route nameRoute Django interna (consigliato per link interni). Autocomplete disponibile.
URL pathURL diretto o link esterno — solo se non c'è una route disponibile.
Ruoli abilitatiLimita la voce a specifici ruoli (per ID). Nessuna selezione = visibile a tutti.
VisibileLa voce compare nel menu.
AttivoIl link è cliccabile.
Nuova tabApre in una nuova scheda del browser.

Creare una nuova voce

  • 1
    Compila il form Nuova voce di navigazione in cima alla pagina.
  • 2
    Il campo Codice è opzionale (viene autogenerato dalla label).
  • 3
    Per link interni: usa Route name — l'autocomplete mostra tutte le route disponibili.
  • 4
    Per Sezione = subnav: inserisci il Gruppo subnav (es. assenze) — indica a quale sezione del portale appartiene.
  • 5
    Premi Crea voce.

Modificare le voci esistenti

La tabella permette modifica inline: clicca direttamente sulle celle, poi premi Salva sulla riga. Per riordinare: trascina con l'handle ⠿ oppure modifica il campo Ord. Usa i filtri per sezione o ricerca testo per trovare rapidamente una voce.

Ruoli abilitati (visibilità per ruolo)

  • 1
    Apri la tabella dei ruoli cliccando su Ruoli Legacy (collassabile in cima).
  • 2
    Usa gli ID numerici nel campo Ruoli abilitati.
  • 3
    Tieni premuto Ctrl (o Cmd su Mac) per selezionare più ruoli.
  • 4
    Nessuna selezione = voce visibile a tutti i ruoli.

Publish / Rollback snapshot

ℹ️
Le modifiche alle voci sono immediate ma non "certificate". Uno snapshot è un salvataggio versionato dell'intera configurazione.
📸 Pubblica snapshot
  • 1
    Inserisci una nota descrittiva (es. "Menu marzo 2026 – aggiunto link RENTRI").
  • 2
    Premi Pubblica snapshot.
↩️ Ripristina snapshot
  • 1
    Seleziona la versione dall'elenco Ripristina snapshot.
  • 2
    Premi Ripristina — la configurazione corrente viene sostituita completamente.
⚠️
Prima di operazioni rischiose (come "Sovrascrivi tutto dal legacy"), pubblica sempre uno snapshot per poter tornare indietro.

Import da legacy

ModalitàEffetto
Merge con legacy consigliato Aggiunge le voci legacy non ancora presenti, senza toccare quelle già configurate.
Sovrascrivi tutto dal legacy distruttivo Elimina tutto e ricrea dal legacy da zero — irreversibile senza snapshot.

Redirect Legacy

Intercetta vecchi URL del portale legacy e reindirizza verso i nuovi percorsi Django.

CampoDescrizione
Legacy pathVecchio URL da intercettare (es. /admin/vecchio-path).
Target routeRoute Django di destinazione (autocomplete disponibile).
Target pathURL path diretto come alternativa alla route.
AttivoDeseleziona per disabilitare temporaneamente senza eliminare.

State Preview (JSON)

Mostra in tempo reale il JSON dell'intera configurazione corrente — identico a quello salvato in uno snapshot. Utile per debug o backup manuale.

5. Permessi
Gestione accessi per ruolo e per utente
📍
Percorso: Admin Portale → Permessi

Modalità: per Ruolo o per Utente

TabEffetto
Per RuoloImposta i permessi standard per tutti gli utenti con quel ruolo.
Per UtenteImposta un override personale che sovrascrive il ruolo per quel singolo utente.

Come funziona la griglia permessi

La griglia mostra una card per ogni modulo, con all'interno i singoli pulsanti.

┌─ Modulo: assenze ───────────────────── [●] toggle modulo ─┐ │ richiesta_assenza /assenze/richiesta [●] │ │ gestione_assenze /assenze/gestione [○] │ │ calendario_assenze /assenze/calendario [●] │ └────────────────────────────────────────────────────────────┘
  • Toggle modulo (in testa alla card): attiva/disattiva tutti i pulsanti del modulo in un colpo solo.
  • Toggle pulsante (riga): controlla il singolo pulsante.
  • Badge parziale = solo alcuni pulsanti del modulo sono attivi. Il toggle modulo diventa giallo (indeterminate).

Azioni bulk (solo modalità Ruolo)

PulsanteEffetto
Tutto ONAttiva tutti i moduli e tutti i pulsanti per il ruolo.
Tutto OFFDisattiva tutto (chiede conferma).
Reset ruoloElimina tutti i permessi del ruolo (torna allo stato "nessuna impostazione").
Copia da + CopiaCopia i permessi da un altro ruolo selezionato.

Override per utente

Nella tab Per Utente, ogni toggle imposta un override personale che ha priorità sul ruolo. Utile per:

  • Dare accesso temporaneo a una funzione senza cambiare il ruolo.
  • Bloccare un singolo utente su una funzione specifica.

Permessi effettivi

In Gestione Utenti, per ogni utente c'è il pulsante Permessi effettivi che mostra la lista completa dei permessi finali (combinazione ruolo + override personale).

6. Wizard: crea pulsante
Procedura guidata in 3 step
📍
Percorso: Admin Portale → Pulsanti → Wizard nuovo pulsante
oppure dall'intestazione della card modulo.
🔵 Step 1 — Dati base
  • Modulo — gruppo di appartenenza (scegli da esistenti o creane uno nuovo).
  • Codice/Azione — slug (es. gestione_assenze). No spazi.
  • Label — testo mostrato nel menu.
  • URL — usa route:nome_route per route interne.
🟡 Step 2 — Permessi iniziali
  • Preset rapido: "Tutti ON", "Tutti OFF", "Solo Admin", ecc.
  • Manuale: espandi il ruolo e imposta singolarmente can_view.
🟢 Step 3 — Riepilogo e salvataggio

Verifica tutti i dati. Il pulsante viene creato e i permessi applicati in un'unica operazione. Dopo la creazione il pulsante è disponibile immediatamente in Permessi e Topbar Live.

🎭
7. Wizard: configura ruolo
Procedura guidata in 3 step
📍
Percorso: Admin Portale → Permessi → pulsante Apri Wizard (in alto a destra dopo aver selezionato un ruolo).
🔵 Step 1 — Seleziona ruolo

Clicca sul ruolo da configurare dall'elenco.

🟡 Step 2 — Configura permessi
  • Toggle modulo per attivare/disattivare l'intero gruppo.
  • Pulsanti ON/OFF per configurazione rapida dentro la card.
  • Espandi per vedere e configurare i singoli pulsanti.
🟢 Step 3 — Riepilogo e salvataggio

Mostra tutti i cambiamenti da applicare. Premi Salva configurazione ruolo per confermare. Ideale per configurare un ruolo appena creato da zero.

8. Flussi per operazioni comuni
Procedure passo-passo per le azioni più frequenti

Aggiungere una voce al menu principale (topbar)

  • 1
    Navigation Builder → form Nuova voce di navigazione.
  • 2
    Sezione: topbar
  • 3
    Route name: scegli dall'autocomplete.
  • 4
    Ordine: inserisci un numero (es. 50 per metterla a metà).
  • 5
    Crea voce. Se l'ordine è sbagliato, trascina dalla tabella o modifica il campo Ord.
  • 6
    (Facoltativo) Pubblica snapshot con una nota descrittiva.

Aggiungere una subnav a un modulo

  • 1
    Navigation Builder → form Nuova voce di navigazione.
  • 2
    Sezione: subnav
  • 3
    Gruppo subnav: inserisci il codice della sezione (es. assenze, anagrafica, assets).
  • 4
    Route name: la pagina specifica.
  • 5
    Crea voce. La subnav apparirà automaticamente quando l'utente è nella sezione corrispondente.

Limitare una voce a un ruolo specifico

  • 1
    Navigation Builder → trova la voce nella tabella.
  • 2
    Campo Ruoli: seleziona i ruoli abilitati (Ctrl+click per più ruoli).
  • 3
    Premi Salva sulla riga.

Dare accesso a un modulo per un intero ruolo

  • 1
    Permessi → tab Per Ruolo → seleziona il ruolo → Seleziona.
  • 2
    Trova la card del modulo e attiva il toggle modulo (attiva tutti i pulsanti in un colpo).
  • 3
    Il salvataggio è automatico — non serve premere Salva.

Creare un nuovo ruolo e configurarlo

  • 1
    Gestione Utenti o Django Admin: crea il ruolo.
  • 2
    Permessi → tab Per Ruolo → seleziona il nuovo ruolo.
  • 3
    Se hai un ruolo simile: Copia da → seleziona il ruolo sorgente → Copia. Poi aggiusta manualmente le differenze.
  • 4
    In alternativa: usa il Wizard configura ruolo per procedura guidata.

Rollback dopo un errore di configurazione

  • 1
    Navigation Builder → sezione Publish / Rollback snapshot.
  • 2
    Seleziona lo snapshot precedente all'errore.
  • 3
    Premi Ripristina → conferma. La configurazione viene ripristinata immediatamente per tutti gli utenti.

Redirect di un vecchio URL

  • 1
    Navigation Builder → sezione Redirect Legacy.
  • 2
    Legacy path = vecchio URL (es. /vecchio/percorso/).
  • 3
    Target route = nome route Django di destinazione (usa l'autocomplete).
  • 4
    Aggiungi redirect. Verifica aprendo il vecchio URL nel browser.

12. ACL Canonico v2 — il nuovo layer permessi
Nuovo in v0.8.6 · /admin-portale/acl-canonico/

Il layer ACL Canonico v2 è il nuovo sistema di controllo accessi basato su permission code espliciti nel formato modulo.risorsa.azione. Convive con il sistema legacy (pulsanti) che rimane attivo come fallback per le route non ancora migrate.

Ordine di risoluzione accessi

1. is_superuser → accesso garantito sempre 2. is_legacy_admin() → accesso garantito alle aree admin 3. RoutePermissionBinding → cerca binding canonico per route o path pattern ↓ trovato? 4. RolePermissionGrant → il ruolo dell'utente ha il grant? 5. UserPermissionGrant → override esplicito per l'utente (priorità sul ruolo) ↓ binding canonico assente? 6. Fallback ACL legacy → pipeline storica (pulsanti → modulo/azione → ruolo)

Concetti chiave

ConcettoDescrizione
Permission codeStringa modulo.risorsa.azione (es. dpi.richieste.view). Non deve contenere spazi.
RoutePermissionBindingAssocia una route Django o un path pattern a un permission code.
RolePermissionGrantAssegna un permission code a un ruolo. Toggle enabled = ON = accesso concesso.
UserPermissionGrantOverride personale utente. Ha priorità assoluta sul grant ruolo.

Operazioni principali

➕ Creare un permission code
  1. Sezione Permission Definitions → form in cima
  2. Code: formato modulo.risorsa.azione
  3. Label: descrizione leggibile
  4. Salva
🔗 Associare una route (binding)
  1. Sezione Route/Path Bindings → form
  2. Scegli Permission code
  3. Route name o Path pattern
  4. Salva — la route è ora coperta dal layer canonico
⚠️
Un binding canonico disattiva il fallback legacy per quella route. Se rimuovi un binding senza grant ruolo corretto, gli utenti riceveranno 403. Per rollback: elimina il binding → il sistema torna al fallback legacy automaticamente.

13. Diagnostica ACL unificata
Nuovo in v0.8.6 · /admin-portale/acl-diagnostica/

Verifica in tempo reale perché un utente ha o non ha accesso a una specifica URL/route. Mostra la decisione finale del resolver v2 con l'intera catena di ragionamento (canonical + legacy).

Come usarla

  1. Seleziona un utente dal dropdown
  2. Inserisci il path (es. /rentri/) o il nome route
  3. Premi Analizza

Campi del risultato

CampoSignificato
DecisioneALLOW o DENY — risultato finale
decision_sourcecanonical, legacy_fallback, admin_bypass, superuser_bypass
Binding canonicoPermission code e route/path abbinati (se presenti)
Grant ruoloIl ruolo dell'utente ha il grant per quel permission code?
Override utenteOverride personale attivo (ha priorità sul ruolo)
Legacy fallbackPulsante trovato, modulo/azione, permesso ruolo nel sistema legacy
TraceSequenza completa dei passaggi di risoluzione

14. Route Coverage Report
Nuovo in v0.8.6 · /admin-portale/acl-route-coverage/

Mappa lo stato ACL di tutte le route Django del portale. Identifica route non protette, coperte solo dal legacy, o già migrate al layer canonico. Export CSV disponibile.

StatoColoreSignificato
CANONICAL_BOUNDVerdeRoute con binding canonico v2 attivo
LEGACY_FALLBACKGialloRoute coperta solo dall'ACL legacy (pulsante)
UNBOUNDRossoRoute senza nessuna protezione ACL configurata
COMING_SOON_EXCLUDEDGrigioRoute esclusa intenzionalmente (coming soon)
REDIRECT_ONLY—Route che fa solo redirect, nessun controllo necessario
💡
Prima di ogni rilascio: verifica che le nuove route siano almeno LEGACY_FALLBACK (non UNBOUND). Usa il filtro per stato e l'export CSV per analisi offline.

15. Mappa Permessi / Navigazione
Nuovo in v0.8.6 · /admin-portale/mappa-permessi-navigazione/

Vista unificata che correla ogni route/pagina con il permission code canonico, i ruoli abilitati, gli override utente, le voci di navigazione (Registry o legacy) e i redirect legacy. Utile per trovare discrepanze tra menu visibile e protezione ACL effettiva.

Filtri disponibili

FiltroDescrizione
RicercaRoute name, path o permission code
SorgenteREGISTRY (Navigation Builder) o LEGACY (pulsanti)
Stato ACLCANONICAL, LEGACY, UNBOUND
RuoloMostra solo le route accessibili a quel ruolo
