GUIDA FUNZIONALE

Portale Applicativo: Moduli e Funzionalità

Documento descrittivo per capire come è organizzato il sistema, cosa fa ogni modulo e come collaborano tra loro.

Aggiornato: 2026-04-02  |  Versione software: 0.8.8

1. Idea Del Programma

Il portale applicativo è una piattaforma interna per gestire processi operativi aziendali, costruita su Django 5.2 e organizzata in moduli indipendenti. Ogni modulo copre un dominio funzionale specifico (assenze, asset, sicurezza, ecc.) e si integra con il sistema di autenticazione e permessi centralizzato.

Obiettivo principale: centralizzare operatività e governance, riducendo attività manuali, errori e dipendenza da modifiche al codice per cambi organizzativi ricorrenti.

I moduli condividono:

  • Un unico sistema ACL basato su ruoli legacy (tabella ruoli + permessi)
  • La topbar dinamica con categorie colorate configurabili senza codice
  • Il sistema di notifiche in-app
  • L'audit trail centralizzato per ogni operazione CRUD rilevante
  • Il monitoring interno per il tracciamento di errori e anomalie applicative

2. Moduli Core e Infrastruttura

CORE

core

Ruolo: fondazione tecnica del portale.

  • Login/logout e collegamento utente Django ↔ utente legacy SQL Server
  • 3 backend auth in cascata: SQLServerLegacy → LDAP/AD → ModelBackend
  • Middleware stack: timeout sessione, impersonation admin, ACL legacy, issue capture
  • Navigation Registry: topbar dinamica con categorie colorate, subnav, sidebar
  • Notifiche in-app per tutti i moduli
  • Audit trail centralizzato (AuditLog)
  • ACL cache versionata con invalidazione condivisa tra worker IIS
  • Compatibility layer Flask (62 route storiche)
CORE

dashboard

Ruolo: punto di ingresso utente.

  • Home page con widget configurabili per ruolo
  • Panoramica rapida moduli disponibili in base ai permessi
  • Preferenze UI per utente: font scaling globale (small/normal/large/xl), sidebar personalizzabile con azioni rapide aggiungibili/riordinabili
  • Navigazione trasversale verso tutti i moduli attivi
GOVERNANCE

admin_portale

Ruolo: pannello amministrativo completo.

  • Gestione utenti, ruoli, permessi (per ruolo e override per singolo utente)
  • Topbar Live: editor rapido ordine e visibilità voci menu
  • Navigation Builder: creazione/modifica voci no-code con snapshot e rollback
  • Wizard nuovo pulsante e wizard configura ruolo
  • Diagnostica LDAP/AD e impersonation utenti
  • Dashboard monitoring e lista issue applicative
INFRASTRUTTURA

hub_tools

Ruolo: hub strumenti interni per amministratori.

  • Module Manager (/hub/moduli/): abilita/disabilita moduli senza riavviare il server
  • Database Manager (/hub/database/): statistiche, backup, pulizia, ottimizzazione, ripristino (SQLite e SQL Server)
  • Schema DB (/hub/database/schema/): mappa visuale infografica di tutti i modelli Django
  • Categorie navigazione (/hub/categorie/): assegna colori e raggruppamenti alla topbar
  • Homepage Builder (/hub/homepage-builder/): layout home page per ruolo
  • Notifiche (/hub/notifiche/): dashboard notifiche, invio manuale, azioni bulk
  • Guide (/hub/guide/): manuali e guide operative
INFRASTRUTTURA

setup_wizard

Ruolo: wizard guidato prima configurazione (12 step).

  • Configurazione DB (SQLite dev / SQL Server prod/test)
  • Configurazione LDAP/AD, SharePoint/Graph, SMTP
  • Selezione moduli opzionali con toggle
  • Creazione utente admin con strength meter password
  • Esecuzione migrazioni e attivazione moduli in tempo reale
  • Rieseguibile da /admin-portale/hub/setup-wizard/
INFRASTRUTTURA

monitoring

Ruolo: osservabilità interna del portale.

  • Tracciamento issue con deduplicazione per fingerprint SHA-256
  • Ciclo di vita issue: new → triage → in_progress → resolved/ignored
  • Cattura automatica eccezioni non gestite, risposte 500/403, richieste lente
  • Pulsante "Segnala problema" nel topnav per tutti gli utenti
  • Monitor automazioni: stato job, fallimenti consecutivi, missing/delayed/failing
  • Alert email anti-rumore con rate-limit per fingerprint (1h)
  • Management commands: monitoring_healthcheck, monitoring_digest
  • Decorator @monitored_automation per job automatici

3. Moduli HR e Workflow

BUSINESS

assenze

Ruolo: gestione ciclo assenze dipendenti.

  • Inserimento richieste di assenza con tipi configurabili
  • Calendario condiviso con vista per reparto/ruolo
  • Workflow di approvazione differenziato per ruolo
  • Certificazioni presenza
  • Sincronizzazione con SharePoint (Microsoft Graph)
  • Trigger SQL Server per alimentare la coda automazioni
BUSINESS

anomalie

Ruolo: segnalazione e gestione anomalie produzione.

  • Form segnalazione con categorie e priorità
  • Lista gestione con filtri avanzati
  • API dati integrazione esterna (ordini/anomalie)
  • Percorsi legacy reindirizzati in sicurezza
BUSINESS

tickets

Ruolo: sistema ticket interni IT e Manutenzione con tracciabilità tempi e KPI.

  • Creazione ticket IT / MAN con categoria dinamica, priorità, assegnatario
  • Allegati privati e commenti con timeline
  • Collegamento a asset aziendali e fornitori
  • Stato IN_ATTESA (bloccato per ricambi/info) oltre ai classici APERTA / IN_CARICO / RISOLTO / CHIUSO / ANNULLATO
  • Categorie dinamiche (IT/MAN) gestibili da admin asset
  • Apertura rapida dalla scheda asset: pulsanti "+ Ticket IT", "+ Ticket MAN" e "+ Intervento esterno" con asset già precompilato
  • Sessioni di intervento: ogni sessione tecnico registra ore, componente, azioni svolte, esito
  • Dati analitici: componente, causa radice, tipo fermo, ore fermo macchina, tecnico risolutore
  • Log strutturato di ogni cambio stato con utente e timestamp
  • KPI per asset: MTTR, ore fermo, ore intervento, top componenti/cause/tecnici visibili nella scheda asset
BUSINESS

notizie

Ruolo: bacheca notizie e comunicazioni interne.

  • Pubblicazione notizie con audience selettiva (reparti/ruoli)
  • Allegati alle notizie
  • Tracciamento letture per utente
  • Visibilità differenziata per ruolo
BUSINESS

timbri

Ruolo: report timbrature dipendenti.

  • Lettura dati in sola lettura dal DB legacy SQL Server
  • Report giornaliero e mensile per dipendente
  • Filtri per reparto e data
  • Gestione anomalie di importazione
BUSINESS

tasks

Ruolo: task management interno.

  • Progetti con task e subtask gerarchici
  • Assegnazione a utenti, scadenze, priorità
  • Commenti e allegati su task e progetto
  • Event log per storico modifiche

4. Moduli Operations e Asset

OPERATIONS

assets

Ruolo: gestione completa degli asset aziendali.

  • Inventario asset con categorie, dettagli IT, ubicazione
  • Work Order: ordini di lavoro con log, allegati, stati
  • Macchine di lavoro (WorkMachine)
  • Verifiche periodiche con scadenzario (collegate a fornitori)
  • Planimetrie interattive con aree e marker clickabili
  • Documenti associati agli asset
  • Etichette personalizzabili con template di stampa
  • Endpoint REST per integrazione esterna (AssetEndpoint)
OPERATIONS

anagrafica

Ruolo: anagrafica dipendenti e fornitori.

  • Profilo dipendente con integrazione AD e DB legacy
  • Ruoli operativi e mansioni (RuoloOperativo)
  • Widget statistiche dipendente (KPI assenze, DPI, tickets, verifiche)
  • Gestione fornitori: documenti, ordini, valutazioni, asset associati
  • Layout statistiche configurabile per ruolo
OPERATIONS

automazioni

Ruolo: designer visuale automazioni business.

  • Costruzione regole con condizioni, azioni e sorgenti dati
  • Trigger via SQL Server (automation_event_queue)
  • Processor: python manage.py process_automation_queue
  • Log esecuzioni per regola e per azione
  • Test regole in sandbox prima dell'attivazione
  • Import/export package di regole
OPERATIONS

rentri

Ruolo: tracciabilità rifiuti (normativa RENTRI).

  • Registro rifiuti con codici EER, produttori, destinatari
  • Conformità alla normativa italiana di tracciabilità rifiuti

5. Moduli Sicurezza e Compliance

SICUREZZA

dpi

Ruolo: gestione Dispositivi di Protezione Individuale.

  • Categorie DPI con immagine, emoji, vita utile e scorta minima
  • Nuova richiesta con card picker visuale per categoria
  • Workflow: INVIATA → APPROVATA/RIFIUTATA → CONSEGNATA
  • Consegna con scadenza auto-calcolata da vita utile
  • Timeline commenti interni per ogni richiesta
  • Storico personale con badge "scaduto/in scadenza"
  • KPI DPI nel dettaglio dipendente (anagrafica)
  • Numerazione automatica: DPI-YYYY-NNNN
  • Notifiche automatiche ad approvazione, rifiuto e consegna
SICUREZZA

procedure_refresh

Ruolo: presa visione obbligatoria procedure MT/MTSI.

  • Anagrafica documenti (codice univoco, tipo MT/MTSI/ALTRO)
  • Revisioni con sorgente SharePoint (URL) o file server (path), unicità revisione corrente per documento
  • Campagne con stati: bozza → pubblicata → chiusa → archiviata
  • Assegnazione massiva utenti con scadenza e revisione selezionata
  • Tracking completo: prima apertura, ultima apertura, contatore letture, IP, user agent
  • Stati assegnazione: assigned → opened → read_confirmed / overdue / cancelled
  • Report per utente, per documento e per campagna
  • Export CSV streaming assegnazioni e riepilogo campagne
SICUREZZA

diario_preposto

Ruolo: diario del preposto sicurezza.

  • Registrazione segnalazioni di sicurezza con allegati
  • Configurazione impostazioni modulo
  • Visibilità per ruolo preposto
SICUREZZA

rilevazione_incidenti

Ruolo: rilevazione incidenti e unsafe condition.

  • SharePoint come fonte di verità (Microsoft Graph API)
  • Cache locale su DB Django per performance
  • CRUD sincronizzato con lista SharePoint
  • Configurazione connessione via impostazioni modulo

6. Come Scorre Una Richiesta

Utente apre pagina → SessionIdleTimeoutMiddleware — verifica timeout inattività sessione → ImpersonationMiddleware — sostituisce request.user se admin sta impersonando → ACLMiddleware — login obbligatorio + verifica permesso per il path richiesto (bypass totale per is_legacy_admin() e is_superuser) → IssueCaptureMiddleware — cattura eccezioni non gestite e risposte lente → context_processors — costruisce topbar_groups, subnav_items, notifiche, preferenze UI → view del modulo (dashboard / assenze / assets / dpi / ...) → rendering template con SSR puro Django
Ogni pagina è visibile solo a chi ha i permessi corretti. Il menu è coerente con il profilo utente e riflette i moduli attivi in SiteConfig.

StratoCosa contienePerché esiste

Django managed Profile, NavigationItem, AuditLog, SiteConfig, Notifica, ModuleCategory, Asset, DPI, ProcedureAssignment, Issue, ... Governance moderna, nuove funzionalità, audit, monitoring, compliance.

SharePoint / Graph Documenti procedure, incidenti/unsafe condition, assenze (sync) Fonte di verità esterna per documenti ufficiali e segnalazioni.

8. Cosa Si Gestisce Senza Toccare Il Codice

Navigazione e UI

  1. Ordinamento e visibilità voci topbar
  2. Creazione/modifica voci di navigazione (topbar, subnav, sidebar)
  3. Abilitazione voci per ruolo specifico
  4. Publish configurazione menu e rollback snapshot
  5. Redirect da vecchi URL legacy a nuove destinazioni
  6. Colore e raggruppamento categorie topbar
  7. Layout home page per ruolo (Homepage Builder)

Moduli e Accessi

  1. Abilita/disabilita moduli senza riavviare il server (Module Manager)
  2. Configura permessi per ruolo (griglia moduli/pulsanti)
  3. Override permessi per singolo utente
  4. Copia configurazione permessi da un ruolo a un altro
  5. Crea nuovi pulsanti ACL con wizard guidato
  6. Impersonazione utente per test (solo admin)

Aree di gestione: /admin-portale/navigation-builder/  ·  /admin-portale/topbar-live/  ·  /admin-portale/permessi/  ·  /admin-portale/hub/

10. Visione Del Programma In Una Frase

Una piattaforma operativa aziendale modulare con 20 moduli attivi, sicurezza ACL per ruolo, processi HR/operations/compliance e governance amministrativa no-code — progettata per evolvere senza deploy a ogni cambio organizzativo.
