Gestione Release — Guida completa

Portale Novicrom · Deployment su Windows Server + IIS · v0.8.3

1. Cos'è il Release Manager

Il Release Manager è una modalità del Setup Wizard che permette di gestire il ciclo di vita di una release (pacchettizzazione e deploy) tramite una interfaccia grafica, senza usare la riga di comando o ricordare i parametri degli script PowerShell.

È composto da due operazioni distinte:

OperazioneDove eseguireCosa fa
Crea Release DEV PC di sviluppo Crea un file .zip dal codice sorgente, pronto per il deploy
Promuovi Release TEST PROD Server Windows Deploya il .zip su un ambiente (estrae, pip, migrate, attiva junction, riavvia IIS)
Nota: Il Release Manager non sostituisce il Setup Wizard per la prima installazione di un ambiente. Usa prima avvia_wizard_TEST.bat o avvia_wizard_PROD.bat per configurare l'ambiente, poi usa il Release Manager per le successive promozioni.

2. Flusso DEV → TEST → PROD

La regola d'oro è: un solo artefatto viaggia da DEV fino a PROD senza essere ricostruito. Il .zip che hai testato su TEST è lo stesso che vai in produzione.

1

Crea Release dal PC di sviluppo

Apri avvia_gestore_release.bat sul PC DEV → Crea Release → scegli la cartella sorgente e la cartella output.

2

Copia il .zip sul server TEST

Copia il file generato (es. portale-novicrom-v0.8.3-20260321_143000.zip) nella cartella C:\PortaleNovicrom\shared\packages\ sul server TEST (via rete, OneDrive, chiavetta USB, SFTP — qualsiasi mezzo).

3

Promuovi su TEST

Sul server TEST apri avvia_gestore_release.bat → Promuovi Release → seleziona il .zip copiato → ambiente TEST → Esegui.

4

Valida su TEST

Verifica che il portale funzioni correttamente sull'ambiente TEST. Controlla i log, testa i workflow critici, verifica le migrazioni.

5

Promuovi su PROD (stesso .zip)

Sul server PROD (o copiando prima il .zip sulla cartella shared\packages\ PROD) apri il Release Manager → Promuovi Release → seleziona lo stesso identico .zip → ambiente PROD → Esegui.

Non ripackaggiare mai per PROD. Usare il codice sorgente una seconda volta introdurrebbe il rischio di differenze rispetto a quanto testato su TEST (modifiche locali non committate, dipendenze diverse, variabili d'ambiente diverse al momento del packaging).

# Apre la schermata di selezione modalità

# Apre direttamente su "Crea Release" (salta la selezione modalità)
python deployment/setup_wizard.py --mode create

# Apre direttamente su "Promuovi Release"
python deployment/setup_wizard.py --mode promote

4. Crea Release (dal PC di sviluppo)

Questa operazione legge il codice sorgente dalla cartella del repository e crea un file .zip compresso, pronto per essere copiato sui server.

Cosa viene incluso nel .zip

Tutti i file del repository ad eccezione delle seguenti categorie:

EsclusoMotivo
.git/Storia git non necessaria in produzione
.venv/ venv/Il venv viene ricreato sul server
.envCredenziali — ogni ambiente ha il suo file
__pycache__/ *.pycCache compilata, non portabile
db.sqlite3DB locale di sviluppo
media/Upload utenti — rimangono sul server
logs/Log locali
staticfiles/Generati da collectstatic sul server
releases/Release precedenti — non vanno zippate
DIPENDENTI.csvDati sensibili

Procedura passo-passo

1

Apri il Release Manager

Esegui avvia_gestore_release.bat (o python setup_wizard.py --mode create). Seleziona Crea Release ← DEV e clicca Avanti.

2

Configura sorgente e output

Cartella sorgente: la radice del repository (es. C:\Dev\Portale Novicrom).
Cartella output: dove salvare il .zip. Default: C:\PortaleNovicrom\shared\packages\.

3

Clicca Esegui

Il wizard crea il file portale-novicrom-vX.Y.Z-YYYYMMDD_HHmmss.zip e verifica la sua integrità. La versione viene letta automaticamente da django_app/config/settings/base.py.

5. Promuovi Release (su TEST o PROD)

Questa operazione prende un file .zip già creato e lo deploya su un ambiente server, eseguendo automaticamente tutte le operazioni di deploy: pip install, collectstatic, migrate, attivazione junction, riavvio IIS.

Prerequisito: l'ambiente deve essere già stato configurato con il Setup Wizard (prima installazione). In particolare devono esistere: il virtualenv in ENV\venv\ e il file ENV\config\.env con le credenziali.

Pipeline automatica

#OperazioneDettaglio
1Estrazione zipEstrae in releases\YYYYMMDD_HHmmss\
2Copia .envCopia ENV\config\.env nel release estratto
3pip installAggiorna le dipendenze Python dal requirements.txt
4collectstaticRaccoglie i file statici in ENV\static\
5Django migrateApplica le nuove migrazioni al database
6createcachetableCrea/aggiorna la tabella cache Django
7Attivazione junctionSalva release precedente, aggiorna junction current\
8Riavvio IISRicicla l'App Pool e avvia il sito

Procedura passo-passo

1

Copia il .zip sul server

Copia il file .zip creato dal DEV in C:\PortaleNovicrom\shared\packages\ sul server destinatario.

2

Apri il Release Manager come Amministratore

Esegui avvia_gestore_release.bat — si auto-eleva automaticamente. Seleziona Promuovi Release → TEST / PROD.

3

Seleziona il pacchetto e l'ambiente

Il wizard rileva automaticamente il .zip più recente in shared\packages\. Seleziona TEST o PROD e verifica la directory base server.

4

Clicca Esegui e attendi

Il log mostra l'avanzamento in tempo reale. Non chiudere la finestra durante il processo. In caso di errore le istruzioni di rollback sono mostrate nella schermata finale.

6. Rollback

Il Release Manager salva automaticamente la release precedente prima di ogni attivazione. Se qualcosa va storto, puoi tornare alla versione precedente in due modi:

Metodo 1 — Script PowerShell (più veloce)

# Rollback TEST (usa la release salvata in run\previous_release.txt)
powershell -ExecutionPolicy Bypass -File C:\PortaleNovicrom\shared\scripts\rollback-release.ps1 -Environment test

# Rollback PROD
powershell -ExecutionPolicy Bypass -File C:\PortaleNovicrom\shared\scripts\rollback-release.ps1 -Environment prod

Metodo 2 — Manuale via junction

# Leggi la release precedente
$prev = Get-Content "C:\PortaleNovicrom\TEST\run\previous_release.txt"

# Aggiorna la junction
cmd /c "rmdir \"C:\PortaleNovicrom\TEST\current\""
cmd /c "mklink /J \"C:\PortaleNovicrom\TEST\current\" \"$prev\""

# Riavvia il pool
Restart-WebAppPool -Name "PortaleNovicrom-TEST"
Rollback in <30 secondi. La junction swap + recycle dell'App Pool è immediata. Non c'è copia di file — punta semplicemente alla directory precedente.

8. Struttura directory server

C:\PortaleNovicrom\
├── shared\
│   ├── packages\          # Dove copiare i .zip da DEV
│   ├── backups\           # Backup ambiente (backup-environment.ps1)
│   └── scripts\           # Script PowerShell copiati dal wizard
│
├── TEST\
│   ├── config\
│   │   └── .env           # Configurazione TEST (non versionata)
│   ├── venv\              # Virtualenv Python (riutilizzato tra release)
│   ├── releases\
│   │   ├── 20260315_103000\   # Release precedenti
│   │   └── 20260321_143250\   # Release attuale
│   ├── current\           # Junction → releases\20260321_143250\
│   ├── static\            # collectstatic output
│   ├── media\             # Upload utenti
│   ├── logs\              # Log applicazione
│   ├── run\
│   │   └── previous_release.txt  # Usato dal rollback
│   └── web.config
│
└── PROD\                  # Struttura identica a TEST
    └── ...
La junction current\ è il punto di montaggio che IIS usa come physical path del sito. Aggiornando la junction si attiva istantaneamente una nuova release senza copiare file.

9. Prerequisiti

Per Crea Release (PC sviluppo)

  • Python 3.11+ con tkinter (incluso nelle distribuzioni Windows standard)
  • Accesso in lettura alla cartella del repository
  • Accesso in scrittura alla cartella output

Per Promuovi Release (server)

  • Python 3.11+ con tkinter
  • Eseguire come Amministratore (richiesto per junction NTFS e IIS)
  • IIS installato con HttpPlatformHandler
  • Ambiente già configurato con Setup Wizard (venv + .env esistenti)
  • ODBC Driver 17 o 18 for SQL Server
  • Il file .zip copiato in shared\packages\

10. FAQ

Il .zip viene rilevato automaticamente?

Sì. Il Release Manager cerca automaticamente il file .zip più recente in shared\packages\ e lo preseleziona. Puoi sempre scegliere un file diverso con il pulsante Sfoglia.

Posso deployare la stessa release più volte?

Sì. Ogni esecuzione di "Promuovi Release" crea una nuova directory in releases\YYYYMMDD_HHmmss\ e aggiorna la junction. La release precedente viene salvata per il rollback.

Cosa succede se migrate fallisce?

Il processo continua ma il log mostra l'errore in rosso. La junction viene comunque aggiornata. Se il portale non funziona dopo il deploy, esegui il rollback con rollback-release.ps1.

Prima di ogni deploy su PROD esegui backup-environment.ps1 -Environment prod -IncludeDatabase per salvare una copia del database.

Come aggiorno il file .env dopo un deploy?

Modifica il file C:\PortaleNovicrom\ENV\config\.env e poi esegui una nuova "Promuovi Release" con lo stesso .zip (o con uno nuovo). Il nuovo .env verrà copiato nel release estratto al passaggio 2 della pipeline.

Posso usare il Release Manager senza avere usato il Setup Wizard?

No. Il Release Manager si aspetta che l'ambiente sia già configurato dal Setup Wizard: il virtualenv ENV\venv\ e il file ENV\config\.env devono esistere. Se uno dei due manca, l'esecuzione si ferma con un messaggio di errore esplicativo.

Quante release vengono mantenute sul server?

Per default il Release Manager non elimina le vecchie release: le mantiene tutte in releases\. Per la pulizia automatica usa lo script PowerShell remove-old-releases.ps1 (mantiene le ultime 5 per default). Puoi anche eliminarle manualmente — l'importante è non eliminare la directory puntata dalla junction current\ e quella salvata in run\previous_release.txt.
