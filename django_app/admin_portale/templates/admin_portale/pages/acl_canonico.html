1. PermissionDefinition 2. Route Binding 3. Role Grant 4. User Override 5. Nav Override
{% if active_tab == 'permissions' %} Step 1 - Permission Definition: è il catalogo dei permessi canonici (es. tickets.view). Qui definisci cosa può essere autorizzato. Un permesso da solo non protegge nulla finché non gli colleghi una route (Step 2) e non lo assegni a un ruolo (Step 3). {% elif active_tab == 'bindings' %} Step 2 - Route Binding: collega ogni route/path al permission code che la protegge. È il punto in cui un permesso inizia davvero a gateare una pagina. Un permesso senza binding non ha effetto; una route senza binding ricade sul fallback legacy. {% elif active_tab == 'grants' %} Step 3 - Role Grant: assegni quali permessi ha un ruolo. È la pagina principale per configurare i permessi per ruolo: seleziona il ruolo nei filtri, spunta i permessi e salva. Vale per tutti gli utenti con quel ruolo. {% elif active_tab == 'overrides' %} Step 4 - User Override: eccezioni per singolo utente che scavalcano i grant di ruolo (allow o deny puntuale). Usalo solo per casi specifici: è più difficile da tracciare rispetto ai grant di ruolo. {% elif active_tab == 'nav-overrides' %} Step 5 - Nav Override: forza la visibilità delle voci di menu per un singolo utente. Riguarda solo la navigazione, non è un confine di sicurezza: l'accesso reale resta deciso da binding/grant/override server-side. {% endif %}
