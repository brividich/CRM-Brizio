Server Windows e controller di dominio: cosa preparare
  1. Sul controller di dominio aggiungere l'account con cui gira il raccoglitore (lo stesso del qcluster) al gruppo di dominio Event Log Readers; sugli altri server al gruppo locale con lo stesso nome.
  2. Nel firewall del server abilitare la regola «Gestione remota registro eventi (RPC)» verso il server del portale.
  3. Nelle policy di audit (GPO «Default Domain Controllers Policy» › Configurazione criteri di controllo avanzati) attivare almeno: Accesso/Disconnessione, Gestione account, Gestione gruppi di sicurezza, Modifica dei criteri di controllo, Convalida delle credenziali, Servizio di autenticazione Kerberos.
  4. Portare il registro Security ad almeno 1 GB (wevtutil sl Security /ms:1073741824): se si riempie prima della lettura, gli eventi più vecchi si perdono e il portale lo segnala come interruzione.
  5. Aggiungere la fonte qui e premere Prova.

Con molti server conviene il Windows Event Forwarding: i server inoltrano a questo server (sottoscrizione «Avviato dall'origine») e qui si aggiunge una sola fonte «Eventi inoltrati».

Accessi ai file, stampe e USB: cosa preparare (come per BusinessLog)

Se BusinessLog è già configurato, policy e voci di controllo sulle cartelle ci sono già e valgono così come sono: basta aggiungere le fonti.

  1. File (file server): nella GPO dei file server «Controlla File system» (Configurazione avanzata › Accesso agli oggetti, operazioni riuscite). Sulla cartella da sorvegliare: Proprietà › Sicurezza › Avanzate › Controllo › Aggiungi, tipo «Operazione completata», «La cartella selezionata, le sottocartelle e i file», con Creazione file/Scrittura dati, Creazione cartelle/Aggiunta dati, Elimina sottocartelle e file, Elimina e Autorizzazioni di lettura (questa registra le aperture). Sulla fonte del file server: «Accessi ai file» e, se servono, le «Cartelle sorvegliate» con le spunte letture, scritture, eliminazioni come in BusinessLog.
  2. Stampe: sui PC e sul server di stampa attivare il registro Microsoft-Windows-PrintService/Operational (via GPO con un'attività immediata: wevtutil set-log Microsoft-Windows-PrintService/Operational /e:true /q:true). Per il titolo del documento: valore DWORD ShowJobTitleInEventLogs = 1 in HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Printers, e sulla fonte «Registra anche il nome del documento».
  3. USB: nella GPO dei PC «Controlla Archivio rimovibile» (Accesso agli oggetti, operazioni riuscite): ogni file copiato, aperto o eliminato su una chiavetta diventa un evento. Per marca e numero di serie della chiavetta: «Controlla attività PNP» (Rilevamento dettagliato). Le chiavette si collegano ai PC: serve la fonte «Tutti i PC del dominio» con «Dispositivi USB».
Tutti i PC del dominio: cosa preparare
  1. Sui PC (GPO): regole del firewall in ingresso «Gestione remota registro eventi» (tutte e tre) verso il server del portale. Se BusinessLog legge già i PC, sono già attive.
  2. L'account del raccoglitore deve poter leggere il registro Security dei PC: gruppo locale Event Log Readers (GPO › Gruppi con restrizioni) oppure, come BusinessLog, un account amministratore dei PC.
  3. Aggiungere una fonte «Tutti i PC del dominio»: l'elenco arriva da Active Directory (computer Windows abilitati, usati negli ultimi 60 giorni) e si aggiorna ogni 6 ore. Ogni PC acceso si legge ogni 10 minuti; un PC spento si riprova dopo 15 minuti e non è un errore.
Insieme a BusinessLog durante il passaggio
  1. In BusinessLog spegnere «Cancella Registro» (Elenco macchine › Impostazioni generali e, se impostato, nella scheda di ogni macchina): di serie svuota il registro Security di ogni macchina a ogni scansione e qui gli eventi tra due letture andrebbero persi (compare l'interruzione «Eventi sovrascritti prima della lettura»).
  2. Scrivere l'account del servizio BusinessLog in Impostazioni › Account dei raccoglitori di log: i suoi accessi a tutti i server ogni pochi minuti restano nell'archivio senza riempire gli accessi degli amministratori.
  3. Tenere i due sistemi insieme almeno un mese, confrontare le stesse giornate (accessi degli amministratori, file di una cartella, stampe) e solo dopo disdire la licenza. L'archivio di BusinessLog va conservato per il periodo già coperto.
ESXi, switch, firewall e NAS (syslog): cosa impostare sull'apparato

Indirizzo da impostare come server syslog: questo server, porta {{ imp.syslog_porta }} ({% if imp.syslog_tcp %}UDP o TCP{% else %}UDP{% endif %}). Esempi:

ESXi (SSH o console): esxcli system syslog config set --loghost='udp://IP-DEL-PORTALE:{{ imp.syslog_porta }}' esxcli system syslog reload esxcli network firewall ruleset set --ruleset-id=syslog --enabled=true vCenter: VAMI (porta 5480) › Syslog › Configura Cisco IOS: logging host IP-DEL-PORTALE + login on-success log + login on-failure log HPE Aruba: logging IP-DEL-PORTALE WatchGuard Firebox: System › Logging › Syslog Server Synology DSM: Centro log › Invio dei log › server syslog

Nel firewall di Windows del server del portale aprire la porta in ingresso solo per gli indirizzi degli apparati. I messaggi da indirizzi non scritti in una fonte vengono ignorati.

Il raccoglitore come servizio di Windows

{% if battito.vivo %}Attivo{% elif battito.at %}Fermo dal {{ battito.at|date:"d/m H:i" }}{% else %}Mai partito{% endif %}

Il raccoglitore è un processo sempre acceso sul server del portale, come il qcluster: si installa una volta e riparte da solo dopo ogni riavvio e ogni aggiornamento del portale.

powershell -ExecutionPolicy Bypass -File C:\PortaleNovicrom\prod\current\deployment\scripts\install-registro-log-task.ps1 -Environment prod

Usa lo stesso account del qcluster (con password: aggiungere -Credential (Get-Credential 'DOMINIO\utente')). Log in C:\PortaleNovicrom\prod\logs\registro_log.log. Prova senza archiviare: manage.py registro_log --prova.
